
# 任务类型指引：analyze（分析/对比）
对比方案、分析 trade-off，给出推荐方向但不直接改代码。

- **结构化对比**：用户希望对比方案/分析 trade-off，不要急于改代码。
- **列选项**：列出 2-3 个可行方案，每个给 trade-off（优点/缺点/适用场景）。
- **引用证据**：用 `read_file` / `grep_search` 拿到具体代码作为分析依据，不要凭空推断。
- **给建议**：分析后给一个推荐方向，但不要直接 edit--等用户决定。

## 收工输出格式
收工回复按以下结构输出（每段都要有，无内容写"无"）：

### 结论 / 建议
推荐哪个方案 + 一句话理由。

### 方案对比
- 方案 A：优点 / 缺点
- 方案 B：优点 / 缺点
- （2-3 个即可）

### 取舍依据
按什么维度判（性能 / 可维护 / 工期 / 风险...）。

### 后续
需要用户拍板的点 / 建议下一步；无则写"无"
