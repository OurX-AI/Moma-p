# URL News Insight Template

## 设计结论

本 skill 面向“输入 URL -> 解析网页 -> 忠实总结 -> 结合核心网和 AI 辅助研发输出启示”的固定流程。最终输出格式不写死在 `SKILL.md` 中，而是从独立模板文件读取：

- `templates/news-url-insight-template.md`

执行任务时必须先读取模板文件，再生成最终答案。

## 工作流程

1. 识别用户输入
   - 提取用户给出的一个或多个 URL。
   - 如果用户给出多个 URL，默认逐个输出；只有在用户明确要求对比或合并时才合并分析。

2. 获取网页内容
   - 优先使用 `web_fetch` 获取网页正文、标题、发布方、作者、发布时间等信息。
   - 如果网页抓取失败、正文不完整、需要动态渲染或存在访问限制，使用 `web_search` 检索官方源、同源页面、可靠转载或标题片段进行补充。
   - 如果仍无法获得充分内容，明确标注“网页内容获取不足”，只基于可验证信息输出。

3. 清洗与验证信息
   - 去除广告、导航、推荐阅读、营销噪声、无关评论等内容。
   - 优先保留原文中的事实、数据、技术描述、发布方观点和场景案例。
   - 对无法确认的信息标注“待验证”；对原文没有的信息写“原文未提及”。

4. 结构化提炼
   - 提炼核心事件、发布方、主要结论、关键技术、方案思路、实践场景、效果数据、限制条件和风险点。
   - 明确区分：原文事实、原文观点、分析推断、业务建议。
   - 不编造原文没有的数据、案例、技术细节或结论。

5. 生成业务启示
   - 结合移动通信核心网设备业务进行迁移分析。
   - 可从以下方向选择最相关内容展开，不要求全部覆盖：
     - AI 智能核心网产品能力建设
     - 软件研发 AI 提效提质：需求、设计、开发、构建、测试、部署、运维、开源治理、漏洞治理
     - 工程体系、平台化、数据闭环、质量保障、试点落地和规模化推广
   - 启示可以合理推断，但必须与原文事实建立清晰关联，措辞保持审慎。

6. 按模板输出
   - 必须读取并遵循 `templates/news-url-insight-template.md`。
   - 保持模板中的一级标题和顺序。
   - 将模板注释替换为实际内容，不要在最终答案中保留 HTML 注释。
   - “详细内容”优先条目化呈现。
   - “可讨论的点（可选）”如有价值，给出 2-5 个内部讨论问题；若无明显讨论价值，可写“暂无”。

## 输出质量要求

- 默认使用中文输出；英文原文中的关键术语可保留英文并做简短解释。
- 先忠实总结原文，再给出业务启示。
- 结论必须有依据；无法验证的信息必须明确标注。
- 对网页访问失败、信息不足、来源冲突等情况要显式说明。
- 输出应适合公司内部分享，语言专业、清晰、克制、可讨论。

## 输出前检查

- 是否已完整处理用户给出的 URL。
- 是否已加载并遵循独立模板文件。
- 是否区分原文事实与个人启示/推断。
- 是否保留关键数据、结论、限制和风险。
- 是否避免编造原文没有的信息。
- 是否体现与 AI 辅助研发、核心网业务或软件工程提效提质的关联。
